# ASCII Video Encoder
#### Video Demo: https://youtu.be/8CmJ8WW1T3c
#### Description:
This project converts a video into an ASCII art rendition of itself with the same frames per second as the original video. When you run project.py, it asks for the path to a video file and opens the file with the OpenCV library. For each frame it extracts it as a NumPy array, then downscales the array to a grid of 120 x 60 cells, so each pixel is taken as an average of what it covers in the cell. The brightness of this is calculated with the Rec. 601 luminance weighting which extracts a brightness value from this. After it associates a brightness value to a corresponding character from the string “.:=+*#%@”, by truncating the value and assigning it to be an integer between 0-7 which can then index the string and produce a corresponding value. Then the character is given a colour based on what the average of the pixels that make up the cell the character inhabits, said average is calculated using INTER_AREA when shrinking the frames so that it averages the nearby pixels to produce a more accurate depiction of what the image would look like. Each of these characters are drawn onto a black canvas(NumPy array) of 1280x720 and the finished frames are saved as output.mp4 after being compiled back into a new video file which is just a bunch of NumPy arrays back to back, occupying the screen for the period of time of one over the frames per second. The file project.py contains a main plus three helper functions; one for downscaling the image to a 120x60 version of itself, another for getting the current frame in the video which the program is looping over given n being the current frame and video being the original video, and lastly the function for retrieving the brightness of the pixel and returning a corresponding character which takes up the relevant amount of pixels.
To install the correct libraries the user needs to do pip install -r requirements.txt this will install the necessary libraries to run the program.
OpenCV strips the video file of its audio so the output.mp4 doesn’t have any audio, a workaround for this could be making use of FFmpeg to stitch back in the audio track from the original video file.
In the future a feature for converting a live video webcam stream to an ASCII art rendition could be implemented, but in order to do that I would need to optimise the program more as I don’t believe that the standard program now could be run in real-time at a stable fps whilst clearing the buffer if it takes too long.
